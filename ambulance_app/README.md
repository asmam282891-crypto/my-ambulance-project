# نظام الإسعاف القومي - ولاية البحر الأحمر

⭐ **التطبيق الآن يستخدم Supabase (سحابة جاهزة 24 ساعة) بدل السيرفر المحلي.**
ما تحتاج بعد اليوم: جهاز مكتب يفضل شغّال، ngrok، DuckDNS، ولا Port Forwarding — Supabase يحل محل كل هذا.

```
ambulance_app/
├── flutter_app/     ← تطبيق Flutter (كل شي فيه الآن)
├── supabase/        ← ملف schema.sql (تشغّله مرة وحدة داخل Supabase)
└── server_dart/     ← ⚠️ قديم/اختياري، ما يعود يُستخدم بعد الانتقال لـ Supabase
```

---

## الإعداد الكامل (مرة واحدة فقط)

### 1) أنشئ مشروع Supabase
1. سجّل مجانًا بـ **supabase.com**
2. اضغط **New Project** → اختر اسم ومنطقة قريبة (مثلاً أوروبا) → أنشئه (ياخذ دقيقة لينشئ قاعدة البيانات)

### 2) شغّل السكيما (الجداول)
1. من القائمة الجانبية بمشروعك: **SQL Editor** → **New query**
2. افتح ملف `supabase/schema.sql` من هذا المشروع، انسخ محتواه كامل، والصقه
3. اضغط **Run** — بينشئ كل الجداول (المستخدمين، الأسطول، البلاغات، التحويلات) دفعة وحدة
4. **إضافة (اختيارية):** لو تبي ميزة الحضور والانصراف للكادر، كرر نفس الخطوة بملف `supabase/attendance_schema.sql` (New query جديد، الصق، Run)

### 3) خذ بيانات الاتصال
من القائمة الجانبية: **Settings (⚙️) → API**
- انسخ **Project URL**
- انسخ **anon public** key

افتح ملف `flutter_app/lib/services/supabase_config.dart` وحطهم مكان القيم الوهمية:
```dart
static const String url = 'https://xxxxxxxxxxx.supabase.co';
static const String anonKey = 'eyJhbGciOi...'; // مفتاح طويل
```

### 4) أنشئ حسابات الدخول الأربعة (المدير، الموظف، المسعف، المستشفى)

بما إن Supabase Auth يدير الحسابات مركزيًا، الإنشاء يصير من لوحة التحكم مباشرة (مرة وحدة بس لكل حساب):

**أ) أنشئ حساب الدخول:**
1. من القائمة الجانبية: **Authentication → Users → Add user → Create new user**
2. Email: `admin@ambulance.local` (استخدم نفس نمط `اسم_المستخدم@ambulance.local`)
3. Password: كلمة مرور قوية (مثلاً `Ps@Admin26`)
4. اضغط **Create user** — بيطلع بالجدول، **انسخ الـ UID** الخاص فيه (رمز طويل)

**ب) اربطه بدوره من جدول profiles:**
1. من القائمة الجانبية: **Table Editor → profiles → Insert row**
2. عبّي:
   - `id`: الصق الـ UID اللي نسخته
   - `username`: `admin`
   - `fullName`: مدير النظام
   - `role`: `admin`
   - باقي الحقول (ambulanceId, hospitalName) اتركها فاضية لحساب المدير

كرر (أ) و (ب) لباقي الحسابات:

| username | email | role | حقل إضافي |
|---|---|---|---|
| `admin` | admin@ambulance.local | `admin` | — |
| `dispatcher` | dispatcher@ambulance.local | `dispatcher` | — |
| `paramedic1` | paramedic1@ambulance.local | `paramedic` | ambulanceId = `1` |
| `hospital1` | hospital1@ambulance.local | `hospital` | hospitalName = اسم المستشفى بالضبط |

### 5) شغّل التطبيق
```bash
cd flutter_app
flutter pub get
flutter run -d chrome
```
سجّل دخول بـ `username` (مو الإيميل) — التطبيق يحوّله تلقائيًا لصيغة الإيميل بالخلفية.

## إضافة مستخدمين جدد لاحقًا

نفس خطوة (4) بالأعلى — من لوحة Supabase مباشرة (Authentication → Add user، ثم صف بـ profiles). زر "كيف أضيف مستخدم؟" بتبويب المستخدمين بلوحة المدير يذكّرك بنفس الخطوات.

## ملحق: تشغيل السيرفر المحلي القديم (اختياري، غير مطلوب الآن)

المشروع كان يشتغل قبل بسيرفر Dart محلي (`server_dart`) بدل Supabase. **بعد الانتقال لـ Supabase، هذا القسم كامل أصبح غير ضروري** — احتفظنا فيه هنا فقط كمرجع لو حبيت ترجع للتشغيل المحلي لأي سبب (تطوير بدون نت مثلاً). التطبيق الحالي **لا يتصل بهذا السيرفر إطلاقًا**.

<details>
<summary>اضغط لعرض تعليمات السيرفر المحلي القديم</summary>

يحتاج تثبيت مكتبة `sqlite3` (ويندوز: حمّل `sqlite-dll-win-x64` من sqlite.org وضع `sqlite3.dll` بمجلد `server_dart`)، ثم:
```bash
cd server_dart
dart pub get
dart run bin/server.dart
```
وللنشر عبر الإنترنت من جهاز شخصي، الملفات `update_duckdns.bat` و `start_server_ngrok.bat` بمجلد `server_dart` لا تزال تعمل لو رجعت لهذا الأسلوب.

</details>

## تسجيل الدخول والأدوار

**مستخدمو الدخول** (بعد ما تنشئهم بلوحة Supabase حسب خطوة 4 بالأعلى):

| الدور | اسم المستخدم | كلمة المرور المقترحة | يشوف |
|---|---|---|---|
| مدير النظام | `admin` | `Ps@Admin26` | كل شي: مستخدمين، أسطول، بلاغات، تحويلات، تقارير |
| موظف بلاغات | `dispatcher` | `Ps@Dispatch26` | إنشاء بلاغات جديدة + نماذج تحويل مستشفيات |
| مسعف | `paramedic1` | `Ps@Medic26` | مهامه المخصصة فقط (مربوط بسيارة إسعاف رقم 1) |
| مستشفى | `hospital1` | `Ps@Hospital26` | الحالات المحوّلة لهم + إرسال طلبات تحويل جديدة |

كل مستخدم بعد تسجيل الدخول يوصله مباشرة للوحته الخاصة حسب دوره.

**لإضافة سيارات إسعاف جديدة**: من لوحة المدير → تبويب "الأسطول" → "إضافة سيارة إسعاف". لازم تضيف السيارة أول، وبعدها تقدر تربط مسعف فيها لما تسوي له حساب بـ Supabase.

⚠️ **ملاحظة أمان:** السياسات الحالية بـ `schema.sql` مبسّطة ومناسبة للتجربة والاستخدام الأولي (RLS مفعّل مع تحقق أساسي من الدور). لاستخدام حقيقي مكثف، راجع سياسات RLS وشدّدها حسب الحاجة.

## شاشات التطبيق

1. **تسجيل الدخول** — نقطة البداية للجميع، يوجّه كل مستخدم للوحته حسب دوره.
2. **لوحة المدير** — 7 تبويبات: البلاغات (توزيع على أقرب إسعاف)، التحويلات (اضغط لعرض التفاصيل الكاملة)، الأسطول (إضافة/حذف سيارات)، المستخدمون (عرض فقط — الإضافة من Supabase)، **الحضور** (تسجيل حضور/غياب/إجازة يوميًا لكل الكادر: أطباء، ممرضين، مسعفين، سكرتارية، محاسبين، فنيين... أي مسمى وظيفي)، التقارير (إحصائيات لحظية)، خريطة عامة.
3. **شاشة موظف البلاغات** — 3 تبويبات: بلاغ جديد، البلاغات (متابعة)، تحويل مستشفى (نموذج STEERING UNIT الكامل).
4. **شاشة المسعف** — قائمة مهامه المخصصة فقط، مع خريطة الموقع وأزرار تدرج الحالة: قبول المهمة → بالطريق للموقع → وصلت للموقع → نقل المريض → إنهاء المهمة.
5. **شاشة المستشفى** — تبويبين: الحالات الواردة (مع زر تأكيد الاستعداد)، وطلباتي المرسلة. زر عائم لإرسال طلب تحويل جديد (اسم مستشفاهم مثبّت تلقائيًا).
6. **نموذج تحويل مريض بين المستشفيات** — نفس حقول النموذج الورقي "STEERING UNIT - PATIENT FORM" بالكامل.

البيانات تتحدث تلقائيًا كل 4-5 ثوانٍ (polling)، أو تقدر لاحقًا تفعّل ميزة Supabase Realtime للتحديث الفوري.

## ملاحظات

- الخرائط تستخدم **OpenStreetMap** (مجانية بدون مفتاح API).
- بيانات المستشفيات بملف `lib/screens/hospital_transfer_screen.dart` (`kHospitals`) — عدّلها لمدينتك الحقيقية (لازم تطابق اسم المستشفى تمامًا مع `hospitalName` اللي تحطه لحساب المستشفى).
- روابط فيسبوك وواتساب بشاشة تسجيل الدخول موجودة بأعلى ملف `lib/screens/login_screen.dart` (المتغيرات `kFacebookUrl` و `kWhatsappUrl`) — عدّلها بروابطكم الحقيقية.
- **قاعدة البيانات حقيقية ودائمة** — Supabase يستخدم PostgreSQL سحابي، البيانات محفوظة دائمًا بدون أي اعتماد على جهازك.
- على أندرويد، صلاحية الموقع تحتاج بملف `android/app/src/main/AndroidManifest.xml`:
  ```xml
  <uses-permission android:name="android.permission.ACCESS_FINE_LOCATION"/>
  <uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION"/>
  ```

## نظام الحضور والانصراف الجديد
- جدول `public.attendance` يعتمد على `user_id`, `attendance_date`, `check_in`, `check_out`.
- جميع العاملين يستخدمون نفس QR الموحد بعد تسجيل الدخول بحسابهم.
- أول مسحة تسجل الحضور، والثانية تسجل الانصراف.
- المدير يضيف المستخدمين من تبويب «المستخدمون» داخل التطبيق عبر دالة `create_staff_user`.
- شغّل `supabase/create_users_function.sql` مرة واحدة بعد تحديثه.
